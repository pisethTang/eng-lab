# Engineering Lab

I've been to a lot of tech events these days to be more informed about different industry practices - how AI is being leveraged in different companies or sectors, different backend & frontend frameworks, software tools such as Atlassian's Jira, Confluence & BitBucket. There was a lot of dense information (insights, tip & tricks) in each event and usually I would go back home and try to recount the important moments from memory and sometimes write up a post about them on LinkedIn or my own personal blog. However due to the volume of meetups *and* I've gone to more technical talks that involved technical concepts (AWS Security Agents, AWS DevOps, FinOps, Atlassian's Planner, Rovo, Software Factory, etc), I found myself thinking about how I can integrate those techniques/workflows into my own personal & professional software development. However, before I can understand anything at a *sufficient*[^1] level, I have to be able to experiment or play around with them in a lab or simulated environment where I can get to tinker around with the code, have a feel of what it's like working with it at different levels of complexity (either creating a small application with said tools or integrating those tools into an existing project). So I want 2 things in one spot: a lab/testing ground and a place where I can document my thoughts and what I learn from a particular meetup. I noticed a need to consolidate all those notes into one spot. I thought of several options: working within GitHub predominantly to create a branch, write about them in markdown files and then do as I see fit with the implementation/usage of those tools. I also thought of creating a software for that but I don't want to overengineer and for the time being, I will try to just use GitHub to do just that.


## Tools
Some tools that I want to incorporate in each lab is to make use of either Exaclidraw or Draw.io (possibly enhanced with AI) to draw out the architecture or workflows.
